Estensione (Ereditarietà)
Parola chiave: extends

Una classe figlia eredita tutti i campi e metodi non privati dalla classe genitore. Java supporta solo ereditarietà singola tra classi (una figlia, un solo genitore diretto). 

class Animale {
  String nome;
  int    eta;

  Animale(String nome) {
    this.nome = nome;
  }

  void mangia() {
    System.out.println(nome + " sta mangiando");
  }

  void descrivi() {
    System.out.println("Sono un animale di nome " + nome);
  }
}

class Cane extends Animale {   // Cane eredita da Animale

  String razza;

  Cane(String nome, String razza) {
    super(nome);             // chiama il costruttore del genitore
    this.razza = razza;
  }

  @Override                   // ridefinisce il metodo del genitore
  void mangia() {
    super.mangia();          // esegue prima la versione del genitore
    System.out.println("... con la crocchetta!");
  }

  void abbaia() {            // metodo aggiunto dalla classe figlia
    System.out.println("Bau bau!");
  }
}
extends super() super.metodo() @Override final → blocca ereditarietà protected → accessibile dalle figlie

✓ Cosa si eredita

  • Campi public e protected
  • Metodi public e protected
  • Interfacce implementate dal genitore
  • Metodi e campi static (visibili, non override)

✗ Cosa NON si eredita

  • Costruttori (vanno richiamati con super())
  • Campi e metodi private
  • Metodi dichiarati final (non si ridefiniscono)
💡 super() deve essere la prima istruzione nel costruttore della classe figlia. Se omesso, Java chiama automaticamente super() senza argomenti — errore se il genitore non ha costruttore vuoto.

Interfacce
Parole chiave: interface · implements

Un'interfaccia è un contratto: definisce cosa una classe deve saper fare, senza specificare come. Una classe può implementare più interfacce contemporaneamente (soluzione al limite dell'ereditarietà singola). 

interface Volante {
  void vola();                // metodo astratto → obbligatorio implementarlo
  void atterra();             // ogni metodo è implicitamente public abstract

  default void descriviVolo() {   // Java 8+: metodo con implementazione
    System.out.println("Sto volando!");
  }

  static Volante crea() {      // Java 8+: metodo statico nell'interfaccia
    return new Aquila();
  }
}

interface Nuotante {
  void nuota();
}

// Una classe può implementare PIÙ interfacce
class Anatra extends Animale implements Volante, Nuotante {

  Anatra(String nome) { super(nome); }

  @Override
  public void vola()    { System.out.println("L'anatra vola bassa"); }

  @Override
  public void atterra() { System.out.println("Atterraggio sull'acqua"); }

  @Override
  public void nuota()   { System.out.println("Quack e via"); }
}
interface implements default (corpo opzionale) static nell'interfaccia campi: solo static final nessun costruttore
Caratteristica Interfaccia Classe astratta
Ereditarietà multipla ✓ Sì (implements A, B, C) ✗ No (solo una extends)
Metodi concreti Solo default e static Sì, liberamente
Campi di istanza ✗ Solo static final ✓ Sì
Costruttore ✗ No ✓ Sì
Uso tipico Capacità / comportamento ("sa fare") Tipo base comune ("è un tipo di")

Polimorfismo
Un'interfaccia, molte forme — risolto a runtime

Una variabile del tipo genitore (o interfaccia) può riferirsi a un oggetto di qualsiasi classe figlia. Quale metodo viene chiamato è deciso a runtime in base al tipo reale dell'oggetto (dynamic dispatch). 

// Polimorfismo con classe genitore
Animale a1 = new Cane("Rex", "Labrador");  // tipo dichiarato: Animale
Animale a2 = new Anatra("Paperino");

a1.mangia();   // → chiama Cane.mangia()   (la versione @Override)
a2.mangia();   // → chiama Animale.mangia() (Anatra non ha override)

// Polimorfismo con interfaccia
Volante[] stormo = {
  new Anatra("Duck"),
  new Aquila("Aquilone"),
  new Aereo("B737")
};

for (Volante v : stormo) {
  v.vola();    // ogni oggetto esegue la propria versione di vola()
}

// Cast esplicito + controllo di tipo (Java 16+: pattern matching)
for (Animale a : animali) {
  if (a instanceof Cane c) {     // se è un Cane, crea var 'c' già castata
    c.abbaia();                    // posso usare i metodi specifici di Cane
  }
  if (a instanceof Anatra anatra) {
    anatra.nuota();
  }
}
@Override instanceof cast esplicito (ClasseFiglia) obj dynamic dispatch pattern matching Java 16+

Override vs Overload — due concetti spesso confusi:

Override (ridefinizione) Overload (sovraccarico)
Quando A runtime (dinamico) A compile-time (statico)
Dove Classi diverse (figlia ridefinisce genitore) Stessa classe
Firma Identica (stesso nome, stessi parametri) Stesso nome, parametri diversi
Annotazione @Override (consigliata) Nessuna
Esempio Cane.mangia() ridefinisce Animale.mangia() somma(int,int) e somma(double,double)
⚠️ Non puoi fare override di metodi static — li puoi solo nascondere (hiding). Con static il metodo scelto dipende dal tipo dichiarato, non da quello reale.

// Esempio completo che usa tutti e tre i concetti
List<Animale> animali = List.of(
  new Cane("Rex", "Labrador"),
  new Anatra("Donald"),
  new Aquila("Arco")
);

for (Animale a : animali) {
  a.mangia();                          // polimorfismo → metodo corretto per ciascuno

  if (a instanceof Volante v) v.vola(); // solo chi implementa Volante vola
  if (a instanceof Cane    c) c.abbaia();
}
